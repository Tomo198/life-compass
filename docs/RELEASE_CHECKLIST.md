# Life Compass リリース前チェックリスト

## 1. UI / 表示

- PCでダッシュボード、家計入力、資産入力、目標管理、年表、シミュレーション、老後プラン、データ管理、設定、法務ページが崩れないこと
- スマホ幅でもナビゲーション、入力フォーム、目標管理、年表、グラフ詳細、データ管理が操作できること
- 目標管理はスマホでも作成・編集・削除できること
- グラフは全点に常時ラベルを出さず、タップした年の詳細だけを表示すること
- 老後プランは表だけでなく、年齢ごとの年末資産をグラフで確認できること
- 数値入力は空欄から入力し直しても先頭に不要な `0` が残らないこと
- 既存値がある数値入力を選択した場合、新しい値へそのまま置き換えられること
- 予算・実績は日別家計簿ではなく、カテゴリ別の月次予算、実績、差額として確認できること

## 2. 計算ロジック

- 家計: 月収、副業収入、ボーナス、固定費、変動費、年間特別支出から月間生活費、毎月貯蓄額、貯蓄率を計算すること
- 予算・実績: 頻度ごとに月平均と年間予算を換算し、選択月の実績との差額を計算すること
- 予算・実績: 家計入力へ反映した場合、毎月固定は固定費、毎月変動は変動費、不定期・年1回は年間特別支出になり、1回だけの支出は年表イベントで扱うこと
- 資産: 現金 + 投資資産 + その他資産 - 負債 = 純資産になること
- 生活防衛資金: 働き方、家族構成、住宅ローン条件から6〜12ヶ月の目安を出すこと
- 年表: 支出イベントは差し引き、収入・資産増イベントは加算し、記録のみは試算に反映しないこと
- 目標: 1回限りの目標は達成済み額と毎月まわす額から達成目安を出すこと
- 継続目標: 頻度ごとの年間必要額と月あたり目安を表示すること
- 取り崩し試算: 開始資金、開始年齢、月額または年率、利回り、物価上昇率から105歳までの年末資産を確認できること
- 取り崩し試算: 開始年齢には取り崩し前の開始資金、翌年齢以降には各年末資産を表示すること
- 老後生活プラン: 年金等、国民健康保険、介護保険、税金の概算入力を反映して年間取り崩し額を計算すること
- 老後生活プラン: 退職時点の試算資産に退職金・一時金を加え、年齢ごとの年末資産と資産寿命を表示すること
- ばらつき試算: 積立、取り崩し、老後生活プランで下位、中央値、上位の範囲と資産が尽きるケース割合を表示すること

## 3. データ管理

- 入力内容はブラウザ内保存で保持されること
- JSONエクスポートにプロフィール、家計、予算・実績、資産、目標、年表、メモ、シミュレーション条件、老後生活プランが含まれること
- JSONインポートでLife Compass形式以外を拒否すること
- 初期化は確認ダイアログを挟むこと
- JSONインポートと初期化の前に復旧用コピーを作り、最大3件から復元できること
- 旧形式のJSONを現行の保存形式へ変換して読み込めること
- 現行アプリより新しい形式のJSONと5MBを超えるJSONを拒否すること
- ブラウザ保存に失敗した場合、画面上に通知してJSONエクスポートを案内すること
- 端末変更やブラウザ削除時はJSONバックアップが必要であることを画面上で説明すること
- 暗号化クラウドバックアップと共同世帯同期は、利用者が明示的に有効化した場合だけ利用すること
- 共同世帯の同時編集は黙って上書きせず、残す内容を選択して他方を復旧用コピーへ保存できること

## 4. 表記 / 法務

- 通常画面で不安を煽る表現を使わないこと
- 個別の金融商品、銘柄、保険商品、暗号資産を推奨しないこと
- `投資助言`、`最適化`、`おすすめ商品`、`高収益保証` のような表現を機能訴求として使わないこと
- シミュレーション結果は `前提条件に基づく試算`、`見通し`、`参考情報` として表現すること
- 国民健康保険、介護保険、税金、年金の表示は制度上の正確な助言や正式計算ではなく、入力条件に基づく概算であることを明記すること
- ばらつき試算は将来予測ではなく、利回りが一定ではない場合の参考情報として表現すること
- 通常の取り崩し試算は老後生活プランと混同しないよう、開始資金と月額または年率による105歳までの単純試算として表現すること
- 利用規約、プライバシーポリシー、特定商取引法に基づく表記、免責事項の雛形があること

## 5. Pro追加前の境界

- 無料版は1つのライフプランを作成・保存・見返し・修正できること
- 無料版は予算・実績履歴、家族別イベント、一定利回りの積立・取り崩し試算を継続利用できること
- Pro予定機能はComing soonとして表示し、Square連携・法務表示・本番テストが完了するまで課金を一般公開しないこと
- Pro予定機能は複数の見直しプラン比較、ライフプラン診断、レビューセンター、固定費見直しインパクト、積立・取り崩しのばらつき試算、退職後設計、暗号化クラウドバックアップを中心にすること
- シナリオ採用前は基本プランを変更せず、採用後は選択条件が反映され、採用前の基本条件が比較用シナリオとして残ること
- 影響分析は順位付けを行わず、変更した前提の直接差と見直しプラン全体の10年後・30年後差を区別して表示すること
- 採用したシナリオ名と採用日がレビューおよびダッシュボードに表示されること
- 同じ月のレビューを画面操作から重複作成できず、計画値、実績値、10年・30年見通し、目標達成目安、TODOが再読込後も残ること
- 月次予算の実績がすべて入力済みの場合だけレビューへ反映でき、不足時は既存レビューを変更しないこと
- レビューから作成した見直しシナリオを編集・比較・採用できること
- 標準保存はブラウザ内保存とJSONバックアップであり、Proの暗号化バックアップと共同世帯同期は任意であることを明示すること
- 課金を追加する場合は、価格、解約方法、返金条件を画面上で明示すること

## 6. 自動テスト

- `npm.cmd run verify` でロジック、Worker API、PC・スマホE2E、本番ビルドが一括で通ること
- `npm.cmd run test:logic` で計算・保存互換性テストが通ること
- `npm.cmd run test:e2e` で最新ビルドを作成し、PC幅とスマホ幅の入力保存、JSON操作、保存失敗通知、Pro境界表示、シナリオ編集・影響分析・採用・再読込、レビューから見直しシナリオ作成が通ること
- PC幅とスマホ幅で共同世帯の自動保存、別端末更新、競合選択、再読み込み後の再開が通ること
- `npm.cmd run build` で本番ビルドが通り、チャンク容量の警告が出ないこと
- GitHub Actionsの月次検証とDependabotの週次確認が有効であること
- `npm.cmd audit --audit-level=high` で高・重大リスクが0件であること
