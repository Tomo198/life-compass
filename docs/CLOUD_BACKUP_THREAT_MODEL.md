# 暗号化クラウドバックアップ 脅威モデル

## 目的と範囲

Life Compassのクラウドバックアップは、Pro利用者が明示的に操作した場合だけ、ライフプランを暗号化してCloudflare R2へ保存する任意機能です。通常の保存先は引き続きブラウザ内であり、自動同期は行いません。

Googleログインは本人識別、D1は契約状態とバックアップメタ情報、R2は暗号化済みバックアップ本体の保存に使います。Google Driveへライフプランを保存しません。

## 守る情報

- 収入、支出、資産、負債
- 家族構成、目標、ライフイベント
- 予算、実績、レビュー、メモ
- シミュレーション条件とシナリオ
- 復旧パスワードと復号鍵

## 保存する情報

### ブラウザ

- 平文の現在プラン
- 利用者が入力した復旧パスワードから一時的に導出した復号鍵

復旧パスワードと復号鍵はLocalStorage、SessionStorage、IndexedDB、Cookieへ保存しません。

### D1

- 利用者ID
- バックアップID
- R2オブジェクトキー
- 暗号化形式のバージョン
- Life Compassデータ形式のバージョン
- 暗号化後サイズ、SHA-256チェックサム、作成・更新日時

### R2

- AES-256-GCMで暗号化されたバックアップ封筒だけ
- PBKDF2のsalt、反復回数、AES-GCMのIV

R2には平文のライフプラン、復旧パスワード、復号鍵を保存しません。

## 暗号化仕様 v1

- 暗号化: AES-256-GCM
- 鍵導出: PBKDF2-HMAC-SHA-256
- 反復回数: 600,000回
- salt: バックアップごとに暗号学的乱数16バイト
- IV: バックアップごとに暗号学的乱数12バイト
- 追加認証データ: `Life Compass encrypted backup v1`
- 復旧パスワード: 12文字以上、200文字以下

暗号化形式にはバージョンを持たせ、将来の方式変更後も旧形式を識別できるようにします。

## 想定する脅威と対策

| 脅威 | 対策 |
| --- | --- |
| R2またはD1の読み取り | R2には暗号文だけを保存し、D1には本文を保存しない |
| 他利用者のバックアップ参照 | Googleログイン済み利用者IDとD1の所有者をすべての操作で照合する |
| CSRF | 状態変更APIで同一オリジンを確認し、CookieにSameSiteを付ける |
| オブジェクトキー推測 | 利用者IDとUUIDから内部キーを生成し、利用者入力のキーを使わない |
| 改ざん | AES-GCM認証タグ、形式検証、暗号文のSHA-256で検出する |
| 大容量送信 | リクエストサイズとバックアップ件数に上限を設ける |
| パスワード総当たり | PBKDF2の反復処理、12文字以上の入力制約、推測しにくいパスワード案内を使う |
| XSSによる平文取得 | CSP、外部スクリプト最小化、復旧パスワードを永続保存しない |
| ログへの機微情報混入 | バックアップ本文、復旧パスワード、Googleトークンをログへ出さない |
| 削除後の残存 | R2削除成功後にD1メタ情報を削除し、アカウント削除でも全オブジェクトを削除する |

## 対応しないこと

- 端末自体が侵害されている場合の平文保護
- 入力中または復号後に悪意あるブラウザ拡張機能が読み取ること
- 復旧パスワードを忘れた場合の運営者による復元
- 自動同期、競合解決、共同編集

## 失敗時の扱い

- R2保存に失敗した場合はD1へメタ情報を作らない
- R2保存後にD1登録が失敗した場合はR2オブジェクトを削除する
- R2削除に失敗した場合はD1メタ情報を残し、再試行できる状態にする
- 復号または形式検証に失敗した場合は現在のブラウザ内プランを変更しない
- 復元直前に現在プランをブラウザ内の復旧用コピーへ保存する

## 本番有効化条件

- R2バケットとWorker Bindingが本番環境に設定済み
- 認証、所有者照合、件数・サイズ上限のAPIテストが成功
- 暗号化・復号・誤パスワード・改ざん検出テストが成功
- PC・スマホで手動保存、復元、削除が成功
- アカウント削除時にR2本体とD1メタ情報が削除される
- プライバシーポリシーとアプリ内説明が実装と一致
