# Life Compass アカウント保護方針

## 保護対象

アカウント機能で保護する対象は、Googleアカウントとの対応、ログインセッション、Pro契約状態、暗号化バックアップと共同世帯へのアクセス権です。ライフプランの平文と復旧・共有パスワードはアカウントDBへ保存しません。

## 認証

- Google IDトークンはWorkerで署名、issuer、audience、有効期限、nonceを検証する
- 利用者の主識別子には変更され得るメールではなくGoogleの`sub`を使う
- nonceは10分で失効し、`HttpOnly`、`SameSite=Strict`のCookieと照合する
- nonceと招待先HMACは固定長SHA-256へ変換して時間差の出にくい比較を行う
- 認証本文は24KBを上限とし、`Content-Length`がない場合もストリーム読取中に停止する
- ログイン試行はCloudflare Rate Limiting Bindingで制限する

## セッション

- セッショントークンは48バイトの暗号学的乱数を使う
- D1には生トークンではなくSHA-256ハッシュだけを保存する
- 本番Cookieは`__Host-`接頭辞、`HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/`を使う
- 有効期限は最長30日とする
- 1アカウントの有効セッションは最大5件とし、超過時は古いものから失効させる
- 利用者は現在端末のログアウトと全端末ログアウトを実行できる
- 期限切れ・失効済みセッションは毎日Cronで削除する

## 機密操作

- アカウント削除、世帯作成、招待、参加者解除、世帯削除は同一Originを必須にする
- アカウント削除と世帯の権限変更は、作成から10分以内の新しいセッションを要求する
- アカウント削除と全端末ログアウトは認証用Rate Limitingの対象にする
- アカウント削除前に有効な契約、所有中の共同世帯、暗号化バックアップを確認する
- 共同世帯のオーナーは、共同世帯を残したままアカウントを削除できない

## 保存情報の最小化

D1へ保存するアカウント情報は内部ID、Google `sub`、確認済みメール、セッションハッシュ、契約状態、共有権限、暗号化保存のメタ情報に限定します。Cookie、Google IDトークン、共有・復旧パスワード、暗号鍵、平文ライフプランを保存またはログ出力しません。

## 本番共有テストの開始条件

1. `HOUSEHOLD_SHARING_MODE=disabled`のままコードを先にデプロイできること
2. リモートD1へ世帯共有マイグレーションを適用済みであること
3. `HOUSEHOLD_INVITE_PEPPER`を専用Secretとして設定済みであること
4. 非公開R2バケットを`SHARED_PLANS`としてバインドしていること
5. 運営者アカウントだけが`preview`で世帯を作成できること
6. 2つのGoogleアカウントで招待、保存、取得、競合、解除、全端末ログアウトを確認すること
7. Cloudflareログへメール、Cookie、トークン、R2キー、ライフプラン本文が出ていないこと
8. 鍵ローテーション、世帯削除、障害時の復旧を確認すること

条件を満たすまでは一般利用者向けの`enforced`へ変更しません。
