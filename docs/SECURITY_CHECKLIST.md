# Life Compass セキュリティ設計チェックリスト

Life Compassは、収入、支出、資産、家族、目標、ライフイベントなどの機微な生活情報を扱うため、ログイン、課金、クラウド保存を入れる前にこのチェックリストを満たすことを前提にします。

## 基本原則

- ライフプラン本文は、標準ではブラウザ内保存のままにする
- サーバー側へ保存する情報は、本人確認、契約状態、暗号化バックアップのメタ情報に限定する
- クラウド保存は利用者が明示的に有効化した場合だけ行う
- サーバー側には、収入、支出、資産、家族情報を平文保存しない
- 秘密鍵、APIキー、webhook署名シークレットはリポジトリに保存しない
- ログ、エラー、問い合わせ対応でライフプラン本文を扱わない

## 現在の骨組み段階

- [x] APIはライフプラン本文を受け取らない
- [x] `/api/backups` の保存処理は未設定として拒否する
- [x] APIレスポンスに `Cache-Control: no-store` を付ける
- [x] D1スキーマはライフプラン本文を保存しない
- [x] Google、Stripe、R2、D1の実接続はまだ行わない
- [ ] APIのレスポンス形式をアプリ側のPro判定と接続する
- [ ] 本番用のD1/R2/KVバインディングを作る前に、保存対象を再確認する

## Googleログイン導入前

- [ ] Googleログインは任意にし、無料版のブラウザ保存はログインなしで使えるようにする
- [ ] ユーザー識別子はメールではなくGoogle IDトークンの `sub` を使う
- [ ] IDトークンはサーバー側で検証する
- [ ] `aud` がLife Compass用のGoogleクライアントIDと一致することを確認する
- [ ] `iss` がGoogle発行元であることを確認する
- [ ] `exp` が期限切れでないことを確認する
- [ ] CSRF対策を入れる
- [ ] セッションCookieを使う場合は `HttpOnly`、`Secure`、`SameSite` を設定する
- [ ] ログイン失敗時にトークン、メール、内部理由をログへ出さない
- [ ] ログインしただけではクラウド保存を開始しない

## Stripe課金導入前

- [ ] Stripe秘密鍵はCloudflare Secretsに保存する
- [ ] Stripe秘密鍵を `VITE_` 付き環境変数にしない
- [ ] Checkout開始APIはログイン済みユーザーだけが使えるようにする
- [ ] Pro判定はフロントエンドの表示ではなくサーバー側の契約状態を使う
- [ ] Stripe webhook署名を必ず検証する
- [ ] webhookイベントIDを保存し、二重処理を防ぐ
- [ ] `customer.subscription.updated` と `customer.subscription.deleted` を処理する
- [ ] `invoice.paid` と `invoice.payment_failed` を処理する
- [ ] テストモードと本番モードのキー、商品ID、価格IDを混在させない
- [ ] カード番号、セキュリティコード、決済情報をLife Compass側で保存しない
- [ ] 解約後のPro利用終了時期を料金ページ、返金方針、アプリ表示で一致させる

## クラウドバックアップ導入前

- [ ] クラウドバックアップはPro向けの任意機能として扱う
- [ ] 利用者が明示的に有効化するまでサーバー保存しない
- [ ] 保存前にブラウザ側で暗号化する
- [ ] R2には暗号化済みJSONだけを保存する
- [ ] D1にはバックアップID、R2キー、サイズ、バージョン、更新日時などのメタ情報だけ保存する
- [ ] 復元用パスワードや復元キーを忘れた場合、運営者が復元できない可能性を明記する
- [ ] バックアップ保存前にJSONサイズ上限を設ける
- [ ] 復元時はJSONバージョンと形式を検証する
- [ ] 自動同期ではなく、まずは手動バックアップ・手動復元から始める
- [ ] 削除操作は確認画面を出し、対象バックアップを明示する
- [ ] 解約後のバックアップ保持期間と削除方法を事前に決める

## API・アプリ共通

- [ ] 状態変更APIは認証とCSRF対策を必須にする
- [ ] APIは許可したHTTPメソッド以外を拒否する
- [ ] エラー表示に内部スタック、秘密値、外部サービスの詳細レスポンスを出さない
- [ ] 入力JSONはサイズ、型、必須項目、バージョンを検証する
- [ ] フロントエンドのPro表示だけを信用しない
- [ ] CORSは原則同一オリジンに限定する
- [ ] `localStorage` の既存データを勝手にクラウド送信しない
- [ ] 問い合わせ導線ではJSONバックアップをメール添付しないよう案内する

## 秘密情報とアカウント管理

- [ ] Cloudflare、GitHub、Stripe、Googleアカウントで多要素認証を有効にする
- [ ] Cloudflare APIトークンはプロジェクトごとに分ける
- [ ] Stripe test/liveの秘密鍵を分ける
- [ ] GitHubに `.env`、秘密鍵、個人情報入りJSONをコミットしない
- [ ] 誤って秘密情報を公開した場合は、削除だけでなく即時ローテーションする
- [ ] Cloudflare Secretsに登録した値を画面共有やログに出さない

## 運用・監視

- [ ] デプロイ前に `test:logic`、`test:worker-api`、`build`、必要に応じて `test:e2e` を通す
- [ ] Cloudflareのデプロイ結果と公開URLの反映を分けて確認する
- [ ] エラー監視では個人データを送らない設定にする
- [ ] 月1回、依存パッケージ、Wrangler、Cloudflare/Stripe/Googleの設定変更を確認する
- [ ] Pro課金開始前に、料金、特商法、返金方針、プライバシーポリシーの整合性を確認する
- [ ] インシデント時の連絡先、初動、停止判断、秘密鍵ローテーション手順を用意する

## インシデント時の初動

1. 影響範囲を確認する
2. 必要ならクラウドバックアップ、課金、ログインAPIを一時停止する
3. 漏えいの可能性がある秘密鍵やトークンをローテーションする
4. D1、R2、Stripe、Cloudflareログの該当期間を確認する
5. 利用者へ説明が必要な場合は、事実、影響範囲、対応策を整理して案内する
6. 原因を修正し、再発防止策をチェックリストへ反映する

## 実装前の合格条件

Googleログイン、Stripe課金、クラウドバックアップを本番化する前に、該当する各章の未チェック項目をすべて確認します。未確認項目が残る場合は、本番公開せず、プレビューまたはローカル検証に留めます。
