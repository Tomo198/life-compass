# Life Compass セキュリティ設計チェックリスト

Life Compassは、収入、支出、資産、家族、目標、ライフイベントなどの機微な生活情報を扱うため、ログイン、課金、クラウド保存を入れる前にこのチェックリストを満たすことを前提にします。

## 基本原則

- ライフプラン本文は、標準ではブラウザ内保存のままにする
- サーバー側へ保存する情報は、本人確認、契約状態、暗号化バックアップのメタ情報に限定する
- クラウド保存は利用者が明示的に有効化した場合だけ行う
- サーバー側には、収入、支出、資産、家族情報を平文保存しない
- 秘密鍵、APIキー、webhook署名シークレットはリポジトリに保存しない
- ログ、エラー、問い合わせ対応でライフプラン本文を扱わない

## 現在の骨組み段階

- [x] APIはライフプランの平文を受け取らず、共有・バックアップではブラウザ暗号化済みJSONだけを受け取る
- [x] `/api/backups` の保存処理は未設定として拒否する
- [x] APIレスポンスに `Cache-Control: no-store` を付ける
- [x] D1スキーマはライフプラン本文を保存しない
- [x] GoogleとD1を接続し、R2は暗号化バックアップだけを限定利用者へ提供する
- [x] APIのレスポンス形式をアプリ側のPro判定と接続する
- [x] Service Workerは `/api/` をキャッシュ対象から除外する
- [ ] 本番用のD1/R2/KVバインディングを作る前に、保存対象を再確認する

## Googleログイン導入前

- [x] Googleログインは任意にし、無料版のブラウザ保存はログインなしで使えるようにする
- [x] ユーザー識別子はメールではなくGoogle IDトークンの `sub` を使う
- [x] IDトークンはサーバー側で検証する
- [x] `aud` がLife Compass用のGoogleクライアントIDと一致することを確認する
- [x] `iss` がGoogle発行元であることを確認する
- [x] `exp` が期限切れでないことを確認する
- [x] nonce Cookie、同一オリジン確認、Google IDトークンのnonce検証を入れる
- [x] セッションCookieは本番HTTPSで `__Host-` 接頭辞、`HttpOnly`、`Secure`、`SameSite=Lax` を設定する
- [x] D1にはセッションCookieの生値ではなくSHA-256ハッシュだけを保存する
- [x] ログイン失敗時にトークン、メール、内部理由をログへ出さない
- [x] ログインしただけではクラウド保存を開始しない
- [x] 利用者自身によるD1アカウント情報の削除導線を設ける
- [x] 期限切れ・失効済みセッションをCronで定期削除する
- [x] 1アカウントの有効セッションを最大5件に制限し、超過時は古いセッションから失効させる
- [x] nonceと招待先HMACは固定長ハッシュを使った時間差の出にくい比較を行う
- [x] 認証APIとバックアップAPIにCloudflare Rate Limiting Bindingを設定する
- [ ] Google Cloudの承認済み生成元を本番URLだけに限定する
- [ ] Cloudflare D1バインディングと本番マイグレーションを確認する

## 決済導入前

- [x] Squareを第一候補、PayPalを代替候補として取扱可否と実装方式を確定する
- [ ] 決済事業者の秘密鍵はCloudflare Secretsに保存する
- [x] 決済事業者の秘密鍵を `VITE_` 付き環境変数にしない
- [x] 決済開始APIはログイン済みユーザーだけが使えるようにする
- [x] Pro判定はフロントエンドの表示ではなくサーバー側の契約状態を使う
- [x] 決済事業者のwebhook署名を必ず検証する
- [x] webhookイベントIDを保存し、二重処理を防ぐ
- [x] 契約開始、更新、解約、支払い失敗を契約状態へ反映する
- [ ] テストモードと本番モードのキー、商品ID、プランIDを混在させない
- [x] カード番号、セキュリティコード、決済情報をLife Compass側で保存しない
- [ ] 解約後のPro利用終了時期を料金ページ、返金方針、アプリ表示で一致させる

## クラウドバックアップ導入前

- [x] クラウドバックアップはPro向けの任意機能として扱う
- [x] 利用者が明示的に有効化するまでサーバー保存しない
- [x] 保存前にブラウザ側で暗号化する
- [x] R2には暗号化済みJSONだけを保存する
- [x] アカウント削除時にR2の暗号化バックアップ本体も削除する
- [x] D1にはバックアップID、R2キー、サイズ、バージョン、更新日時などのメタ情報だけ保存する
- [x] 復元用パスワードや復元キーを忘れた場合、運営者が復元できない可能性を明記する
- [x] バックアップ保存前にJSONサイズ上限を設ける
- [x] 復元時はJSONバージョンと形式を検証する
- [x] 自動同期ではなく、手動バックアップ・手動復元から始める
- [x] 削除操作は確認画面を出し、対象バックアップを明示する
- [x] 解約後も保存済みバックアップを保持し、本人による復元・削除またはアカウント削除まで自動削除しない

## API・アプリ共通

- [x] 状態変更APIは認証と同一オリジン確認を必須にする
- [x] APIは許可したHTTPメソッド以外を拒否する
- [x] エラー表示に内部スタック、秘密値、外部サービスの詳細レスポンスを出さない
- [x] 認証・暗号化バックアップ・共有プランの入力JSONはストリーム読取中にも上限を適用し、型、必須項目、バージョンを検証する
- [x] Worker側で新規保存のPro権限を再判定し、一覧・復元・削除はログイン済み本人の所有権で制御する
- [x] 状態変更APIは同一オリジンに限定し、CORSで外部オリジンへ公開しない
- [x] `localStorage` の既存データを勝手にクラウド送信しない
- [x] 問い合わせ導線ではJSONバックアップをメール添付しないよう案内する

## 秘密情報とアカウント管理

- [ ] Cloudflare、GitHub、決済事業者、Googleアカウントで多要素認証を有効にする
- [ ] Cloudflare APIトークンはプロジェクトごとに分ける
- [ ] 決済事業者のテスト用・本番用秘密鍵を分ける
- [ ] GitHubに `.env`、秘密鍵、個人情報入りJSONをコミットしない
- [ ] 誤って秘密情報を公開した場合は、削除だけでなく即時ローテーションする
- [ ] Cloudflare Secretsに登録した値を画面共有やログに出さない

### 既知の依存関係警告

- 2026-07-24時点で、開発用`wrangler 4.112.0 -> miniflare -> sharp 0.34.5`に修正版のないHigh警告が3件ある
- `npm audit --omit=dev --audit-level=high`では本番依存の脆弱性は0件
- `sharp`は公開SPAやWorkerの本番バンドルへ含めず、Wrangler更新時に解消状況を再確認する

## インシデント時の初動

1. 影響範囲を確認する
2. 必要ならクラウドバックアップ、課金、ログインAPIを一時停止する
3. 漏えいの可能性がある秘密鍵やトークンをローテーションする
4. D1、R2、決済事業者、Cloudflareログの該当期間を確認する
5. 利用者へ説明が必要な場合は、事実、影響範囲、対応策を整理して案内する
6. 原因を修正し、再発防止策をチェックリストへ反映する

## 実装前の合格条件

Googleログイン、課金、クラウドバックアップを本番化する前に、該当する各章の未チェック項目をすべて確認します。未確認項目が残る場合は、本番公開せず、プレビューまたはローカル検証に留めます。
